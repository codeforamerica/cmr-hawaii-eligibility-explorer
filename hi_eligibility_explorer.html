Clean Slate Eligibility Rules Engine Proof of Concept — Hawaiʻi

A demonstration of how eligibility rules can be programmed and record eligibility can be determined using automation. All records shown are synthetic.

This is a proof of concept for a Clean Slate “rules engine.” The page runs a set of toggleable eligibility rules over synthetic criminal records to show that eligibility for shielding can be determined by code. Change the rules and the code updates, showing you which records become eligible and which don't. Every outcome comes with a reason, so you can follow the logic.

Clean Slate is initiated by a single agency, and different agencies keep different records. This tool uses synthetic data that was modeled on the front-end views of court records in eCourt Kōkua and arrest records in eCrim. (The tool does not touch real records or people's personal information.) You can choose which agency is running the check and see the results based on that agency's version of the record data. Notably, the rules are designed to work for either agency's data.

The takeaway: grade-level eligibility, charge-level exclusions, and waiting periods are all workable here, because each rule relies only on data already present in the initiating agency's records.

How a record gets read

Show

This page is the rules engine. The counts and the record list above were not worked out somewhere else and pasted in. They are computed here, in your browser—which is why the numbers move the instant you touch a control.

For rules to run, the data must be usable, meaning relevant free text in a record has to be turned into fields a rule can use—the top half of the code below. The code does this for the offense grade, statute section, disposition, and imposed sentence. The rules then apply to those standardized fields—the bottom half of the code.

The page's version of the code is written in JavaScript, the main language that interactive features on webpages are built on, and it runs inside your browser. Code for America first built the rules engine using a different programming language, called Python, which runs on a computer instead. That version was put through a full test suite and checked against an answer key derived outside of the rules engine.

Writing the rules engine code twice was deliberate for this proof of concept. Two versions written separately have to agree, so a mistake in either one surfaces as a disagreement instead of a confident wrong answer. The badge at the top of the page shows that comparison—it confirms the audited Python version and the JavaScript running in your browser arrive at the same results. You can toggle between the two versions of the code below.

The patterns and every worked example above are taken from the code itself, not retyped: the Python answers are captured when this page is built and the JavaScript is re-run each time you open it, and the badge above turns red if the two ever stop matching.

Synthetic data — a proof of concept for Hawaiʻi's Clean Slate effort. All names, dates, and identifiers (case, arrest, and ID numbers) are randomly generated and fabricated to resemble each agency's real systems; they depict no real person or record, and any resemblance to an actual person or case is coincidental. The eligibility criteria are illustrative policy choices, not enacted law, and this is not legal advice.
